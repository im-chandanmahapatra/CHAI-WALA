## 1. Prerequisites & Environment Setup

### 1.1 System Requirements

- **Node.js:** v18.0.0 or higher (v20+ recommended)
- **Package Manager:** `npm` (v9+) or `pnpm`
- **Python (for testing & reporting scripts):** Python 3.10+
- **Playwright:** Python Playwright (`pip install playwright && playwright install chromium`)

### 1.2 Repository Clone & Initial Install

```powershell
# Clone the repository
git clone https://github.com/im-chandanmahapatra/CHAI-WALA.git
cd CHAI-WALA

# Install frontend dependencies
cd client
npm install
cd ..
```

### 1.3 Environment Configuration

The application works 100% out-of-the-box in local mock mode without external dependencies. To connect a live Supabase database:

```powershell
cp client/.env.example client/.env.local
```

Edit `client/.env.local`:
```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

> [!WARNING]
> Never place a Supabase service-role key or private secrets in `client/.env.local`. Client-side `VITE_*` environment variables are exposed in production bundles.

## 3. Testing & Quality Assurance

The repository includes a comprehensive, multi-layer verification suite covering audio streaming, UI responsiveness, cart invariants, and checkout.

### 3.1 Music Integration & Player Test Suite (10 Scenarios)

The end-to-end audio suite validates playback, seeking, theme transitions, and event synchronization across desktop and mobile viewports:

```powershell
# 1. Build the production bundle
npm --prefix client run build

# 2. Run the automated Playwright test suite
python tests/test_music_integration.py
```

#### Verified Scenarios:
1. **Initial Page Load & Station Rendering:** Validates `#radio` station mount in 1900s Adda theme.
2. **Audio Element Lazy Mount:** Confirms audio element does not mount or autoplay before user interaction.
3. **1900s Theme Playback:** Verifies playback of vintage Adda continuous stream (`/audio/90s_playlist.mp3`).
4. **Theme Switch to 2020s Café:** Verifies switch to 2020s Café playlist without audio bleeding.
5. **2020s Track Manifest:** Confirms track title, artist, and duration match the verified 35-track library.
6. **Next & Previous Track Transport:** Verifies skipping forward and backward through the playlist.
7. **Accurate Draggable Audio Seeking (to 01:35):** Dispatches programmatic drag scrubbing to exactly `01:35`, confirming `audio.currentTime` updates accurately.
8. **Volume & Mute Controls:** Validates mute toggle and volume slider responsiveness.
9. **Mobile Viewport Responsiveness:** Checks layout, tap targets, and touch interactions on iPhone 14 (390×844).
10. **Single Audio Instance & Console Cleanliness:** Confirms at most 1 `<audio>` element exists in the DOM and zero unexpected runtime errors occur.

Screenshots generated by the test run are saved to `artifacts/screenshots/`.

### 3.2 UI Order Invariant Tests

Validates cart calculations, option toggles, tax/packaging rules, and checkout tickets:

## 4. Local Audio Library Management

The 2020s Café Radio plays a curated set of local music files located in `client/public/audio/2000s/`.

### 4.1 Adding or Updating Audio Tracks

1. Place the optimized `.mp3` files in `client/public/audio/2000s/`.
2. Format the filename cleanly or preserve standard naming (e.g., `track_name.mp3`).
3. Update `client/src/lib/cafe-library-manifest.ts` with track details:
   ```typescript
   {
     id: "track_id",
     fileName: "track_file.mp3",
     title: "Verified Song Title",
     artist: "Artist Name",
     duration: 215, // in seconds
     durationFormatted: "03:35",
     fileSize: 5242880,
     status: "identified" // or "unknown"
   }
   ```
4. Update `client/public/audio/2000s-manifest.json` for external JSON consumers.
5. Rebuild with `npm --prefix client run build` and run `python tests/test_music_integration.py`.

### 4.2 HTTP 206 Partial Content Requirement

For smooth seeking, the web server serving audio files must support HTTP `Range` requests with `206 Partial Content` and `Accept-Ranges: bytes` headers.
- **Production (Vercel, Netlify, Nginx, Cloudflare):** Handled natively by modern CDNs.
- **Test Server:** Built into `tests/test_music_integration.py` via `RangeHTTPRequestHandler`.

## 6. Deployment Guide

### 6.1 Vercel Deployment (Active V2 Production vs. V1 Client)

**Active V2 Production (Repository Root via `vercel.json`):**
1. Connect `im-chandanmahapatra/CHAI-WALA` in the Vercel dashboard (Production Branch: `main`).
2. Leave **Root Directory** empty (`.` — repository root) so both `v2/` and the shared `client/public/audio/` directory deploy together.
3. Set **Framework Preset** to **Other** (root `vercel.json` specifies `"framework": null`, `"buildCommand": null`, `"outputDirectory": "."`, and redirects `/` → `/v2/`).

**Legacy V1 Standalone Client Only (`client/`):**
1. Set **Root Directory** to `client` and **Framework Preset** to **Vite**.
2. Optionally configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` if deploying with live Supabase.

### 6.2 Supabase Database Migration

To apply the database schema to your Supabase instance:
```powershell
# Using Supabase CLI
supabase db push
# Or copy content from supabase/migrations/20261025_init_schema.sql into Supabase SQL Editor.
```
